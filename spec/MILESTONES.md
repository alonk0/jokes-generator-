# MILESTONES – מחולל בדיחות מבוסס AI

**מסמכי ייחוס:** `PRD.md`, `ARCHITECTURE.md`, `DESIGN.md` (לרבות `wireframes.png`, `style-guide.png`, `mockups.png`).

**היקף מחייב:** מוצר בעל **עמוד אחד** בעברית וב-RTL. התצוגות המכונות בתמונות "מסך הבית" ו"מסך בדיחה" הן מצבים של אותו עמוד; **מסך אודות**, קישורי מדיניות, שיתוף ותמונות בדיחה שנוצרות אוטומטית אינם נכללים במוצר. אין Database או Authentication.

## Milestone 1 – בסיס הפרויקט וממשק שימושי

**מטרה:** להעמיד אפליקציית Web עובדת, שניתן להריץ ולבדוק, עם מבנה הממשק המאושר לפני חיבור שירות ה-AI.

**מה יש לממש:**
- הקמת פרויקט `Next.js (App Router) + React + TypeScript`, ניהולו ב-`Git` וב-`GitHub Repository` אחד והגדרת אפשרות הרצה ובנייה מקומיות.
- בניית עמוד יחיד רספונסיבי בהתאם ל-`DESIGN.md`: כותרת, טקסט הסבר, שדה נושא עם `Placeholder` בעברית, מונה תווים, כפתור "צור בדיחה" ואזור תוצאה. שימוש ב-`CSS Modules` או CSS רגיל; RTL, צבעים, טיפוגרפיה ורכיבים תואמים למקורות העיצוביים.
- אכיפת 100 תווים בממשק; התיבה יכולה להיות ריקה. שינוי התיבה לא משנה תוכן שכבר מוצג.
- הכנת מצבי ממשק בסיסיים והדגמה מקומית של תוכן בדיקה **ללא קריאת OpenAI**; ברור למשתמש שזו הדגמה בלבד ולא יצירת בדיחה אמיתית.

**תוצר מצופה:** אתר מקומי פעיל שבו ניתן להזין נושא, לראות את מבנה העמוד ואת אזור התוצאה ולבחון את העיצוב במכשירים שונים. אין עדיין יצירה אמיתית באמצעות AI.

**Definition of Done:**
- [ ] הפרויקט נמצא ב-GitHub וניתן להרצה מקומית; פקודות `Build` ובדיקות איכות קוד שהוגדרו לפרויקט עוברות.
- [ ] קיים עמוד מוצר אחד בלבד, ללא מסך אודות, תפריטי ניווט או תכונות שלא אושרו.
- [ ] שדה הנושא מקבל קלט ריק, מציג מונה ומונע קלט מעל 100 תווים; שינוי הנושא בלבד אינו משנה תוצאה מוצגת.
- [ ] הממשק בעברית וב-RTL, והפריסה שמישה במובייל, בטאבלט וב-Desktop בדפדפנים מודרניים.
- [ ] ניתן להציג ולהסיר תוכן בדיקה באזור הבדיחה ללא שגיאות, ואין מצג של חיבור AI אמיתי.

## Milestone 2 – יצירת בדיחה אמיתית עם Streaming

**מטרה:** לספק את יכולת הליבה המלאה מקצה לקצה: הזנת נושא וקבלת בדיחה בעברית בהדרגה דרך Backend מאובטח.

**מה יש לממש:**
- יצירת `POST /api/joke` ב-`Next.js Route Handler` עם `Node.js Runtime`, אימות קלט בצד השרת (כולל 100 תווים) ובחירת נושא כללי עבור קלט ריק.
- חיבור ל-`OpenAI Responses API` באמצעות ה-`OpenAI JavaScript SDK` הרשמי והמודל **`gpt-5` בלבד**. יצירת בדיחה אחת בכל בקשה, בעברית בלבד, עם אורך וסגנון חופשיים.
- ניהול `OPENAI_API_KEY` בצד השרת בלבד באמצעות `.env.local` שאינו מועלה ל-Git; הוספת `.env.example` ללא ערכים סודיים.
- הזרמת טקסט מהשרת לדפדפן ב-`HTTP Streaming` לפי חוזה ה-`SSE` שב-`ARCHITECTURE.md` (`delta`, `complete`, `error`), ועדכון אזור התוצאה בהדרגה.
- בלחיצה חדשה, החלפת הבדיחה הקודמת בבדיחה אחת חדשה; אין שמירת היסטוריה. תוצאה נחשבת להושלמה רק לאחר אירוע `complete`.

**תוצר מצופה:** אפשר לכתוב "חתולים" או להשאיר את התיבה ריקה, ללחוץ "צור בדיחה" ולראות בדיחה אמיתית בעברית מופיעה בהדרגה באותו עמוד.

**Definition of Done:**
- [ ] בשני התרחישים — נושא מוזן ונושא ריק — מתקבלת בדיחה אחת אמיתית באמצעות `gpt-5` דרך ה-Backend, והטקסט מוצג ב-Streaming.
- [ ] נושא לועזי מניב בדיחה בעברית; יצירה נוספת מחליפה את התוצאה הקודמת ולא מוסיפה רשימת בדיחות.
- [ ] בקשת API עם נושא מעל 100 תווים או בקשה לא תקינה נדחית בשרת, גם ללא שימוש בממשק.
- [ ] השלמה מזוהה לפי אירוע `complete`, ולא רק לפי סגירת החיבור.
- [ ] אין מפתח API, Prompt שרת או מידע סודי בחבילת ה-Frontend, בתגובות API או ב-GitHub; לא מתבצעת קריאת OpenAI ישירה מהדפדפן.
- [ ] `Build` ובדיקת זרימת הבקשה מקצה לקצה עוברים בסביבת פיתוח; אין עדיין חשיפה ציבורית ללא הגנות ה-Production שנקבעו בארכיטקטורה.

## Milestone 3 – עצירה, העתקה וטיפול במקרי קצה

**מטרה:** להשלים את כל ההתנהגויות שהמשתמש צריך במהלך יצירה מוצלחת, עצירה או כשל, ללא הוספת מסכים.

**מה יש לממש:**
- החלפת "צור בדיחה" ב-"עצור" בזמן `Streaming`; ביטול באמצעות `AbortController` והעברת ביטול ל-Backend/OpenAI ככל שניתן. הגנה מפני מקטעים מאוחרים של בקשה ישנה (`requestId` או מנגנון שקול).
- השארת הטקסט החלקי בעת עצירה או ניתוק, וחזרה לאפשרות ליצור בדיחה חדשה.
- כפתור "העתק בדיחה" עם `Clipboard API`, פעיל **רק** כשהבדיחה הושלמה בהצלחה; טיפול בכשל העתקה ללא חשיפת שגיאה טכנית.
- הודעות שגיאה בעברית והזדמנות לנסות שוב בכשל רשת, כשל שירות AI, קטיעת Stream ותגובה חריגה. טיפול בתשובת `429` של WAF גם כאשר הגוף אינו `SSE` או JSON.
- הבחנה נכונה בין `completed`, `stopped`, `error` ובין היעדר אירוע `complete`; מניעת העתקת טקסט חלקי דרך הכפתור.

**תוצר מצופה:** משתמש יכול לעצור יצירה, להעתיק בדיחה שהושלמה, ולהמשיך להשתמש באתר בצורה צפויה גם לאחר ניתוק רשת או תקלה בשרת.

**Definition of Done:**
- [ ] בזמן Streaming מוצג "עצור"; לחיצה עליו עוצרת הצגת מקטעים חדשים ושומרת את הטקסט החלקי שכבר התקבל.
- [ ] טקסט חלקי שנעצר או נקטע אינו ניתן להעתקה דרך הכפתור; בדיחה שהושלמה מועתקת במלואה ל-Clipboard.
- [ ] ניתוק לפני קבלת טקסט, ניתוק לאחר קבלת טקסט ולפני `complete`, תקלה ב-AI והיעדר אינטרנט בעת ניסיון יצירה מציגים הודעות שגיאה בעברית ומאפשרים ניסיון חדש.
- [ ] גם כאשר הבקשה הסתיימה ללא `complete`, הממשק אינו מסמן אותה כהצלחה.
- [ ] בקשות ישנות או אירועים שהגיעו לאחר ביטול אינם משנים תוצאה של בקשה חדשה.
- [ ] בדיקת תגובת `429` מאמתת שהממשק מציג הודעת הגבלת קצב ברורה ואינו חושף תגובת שרת גולמית; בדיקת אכיפת WAF אמיתית תתבצע ב-Milestone 4.

## Milestone 4 – PWA, הגנת שימוש ו-Deployment

**מטרה:** להעמיד גרסת Production ניתנת להתקנה ולשימוש, עם הגנת Rate Limiting, פריסה אוטומטית והתנהגות Offline תואמת PRD.

**מה יש לממש:**
- `Web App Manifest`, אייקונים ונכסי PWA נדרשים, `Service Worker` ו-`Cache Storage` עבור `App Shell` בלבד. בקשות `POST /api/joke` אינן נשמרות ב-Cache; תשובות API מוגדרות `no-store`.
- פתיחת הממשק גם ללא אינטרנט אחרי ביקור מחובר והכנת ה-Cache; ניסיון ליצור בדיחה ללא רשת מציג הודעת שגיאה בעברית. ההתקנה מתבצעת דרך אפשרויות הדפדפן, **ללא כפתור התקנה באתר**.
- חיבור GitHub ל-Vercel עם `Preview Deployments` לענפי עבודה ו-`Production Deployment` מתוך `main`, כולל `Build` אוטומטי ו-HTTPS.
- הגדרת `OPENAI_API_KEY` ב-Vercel Environment Variables לצורך הרצת Backend, עם הפרדת הגדרות מקומיות/Preview/Production לפי הארכיטקטורה; בדיקת זמינות `gpt-5` ותאימות מגבלות זמן של Functions ל-Streaming.
- הגדרת `Vercel WAF Rate Limiting` ל-`POST /api/joke`: חמש בקשות בדקה לכל כתובת IP בחלון קבוע של 60 שניות, החזרת `429` בעת חריגה, ללא מכסה יומית וללא Database. החלת הגנה גם על סביבת ה-Preview שבה משתמשים לבדיקות, ולא רק על Production.
- בדיקות קבלה של כל זרימות המוצר בדפדפנים ומכשירים רלוונטיים, יחד עם בדיקת הגבלות Hosting, הוצאות API ולוגים תפעוליים בסיסיים ללא תוכן בדיחות.

**תוצר מצופה:** גרסה ציבורית נגישה ב-HTTPS עם Deployment אוטומטי מ-GitHub, יצירת בדיחות מוגנת Rate Limiting, התקנה כ-PWA וממשק שנפתח Offline.

**Definition of Done:**
- [ ] המוצר מותקן כ-PWA באמצעות מנגנוני התקנה נתמכים בדפדפן/מערכת ההפעלה, ללא כפתור התקנה בתוך האתר.
- [ ] אחרי טעינה מחוברת, ממשק האפליקציה נפתח גם ב-Offline; לחיצה על "צור בדיחה" ללא רשת מציגה הודעה בעברית ולא מחזירה בדיחה מתוך Cache.
- [ ] `POST /api/joke` מוחרג מ-Cache; כותרות תשובת API מונעות שמירה, וקובצי App Shell הדרושים זמינים Offline.
- [ ] חיבור GitHub–Vercel יוצר Preview בעקבות שינוי בענף עבודה ו-Production בעקבות מיזוג מאושר ל-`main`, ללא פריסה ידנית בכל שינוי.
- [ ] ב-Preview וב-Production הרלוונטיים, בדיקת עומס מבוקרת ומותרת מאותה כתובת IP מאמתת שהבקשה השישית באותו חלון זמן נדחית ב-`429` **לפני** קריאה ל-OpenAI, והודעת החריגה מוצגת בעברית.
- [ ] ה-API Key זמין ל-Backend בלבד באמצעות משתני סביבה; אינו נחשף בדפדפן, בבנייה או ב-Repository.
- [ ] בדיקות קבלה עוברות: נושא ריק/מוזן/לועזי, 100 תווים, Streaming, עצירה, העתקה לאחר השלמה בלבד, החלפת בדיחה, כשלי רשת ושירות, Rate Limiting ו-Offline.
- [ ] נבדקו מגבלות Vercel, תנאי התוכנית הרלוונטית, זמינות GPT-5 והגדרות מעקב עלויות לפני חשיפה ציבורית; לא מבוצעת פריסת Production לפני שהגנות המערכת פעילות.

## Development Execution Rules – כללי ביצוע הפיתוח

**הוראה מחייבת ל-AI שמבצע את הפיתוח:**

1. יש לפתח את ה-Milestones **לפי הסדר בלבד**, על בסיס מסמכי ה-PRD, הארכיטקטורה והעיצוב, ללא הוספת פיצ'רים שלא אושרו.
2. בסיום **כל Milestone**, יש **לעצור את הפיתוח**, להציג למשתמש את התוצר שהושלם, איך ניתן לבדוק אותו ואת תוצאות הבדיקות מול **כל סעיף** ב-Definition of Done (עבר / נכשל / טרם נבדק), כולל תקלות או חסמים פתוחים.
3. **אסור להתחיל את ה-Milestone הבא ללא אישור מפורש של המשתמש**, גם אם כל הבדיקות עברו.
4. אין לסמן Milestone כ-Done כאשר תנאי סיום מהותי לא אומת. אם בדיקה דורשת שירות חיצוני, הרשאה או הגדרת חשבון, יש להסביר למשתמש במילים פשוטות מה נדרש ולהמתין להשלמתו.
5. אין להשתמש ב-Mockups כהיתר להרחיב את ה-PRD: מסך האודות וקישורי המדיניות שמופיעים בתמונות אינם חלק ממסלול הפיתוח הנוכחי.
