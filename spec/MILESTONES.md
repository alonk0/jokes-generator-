# MILESTONES – מחולל בדיחות מבוסס AI

**מסמכי ייחוס:** `PRD.md`, `ARCHITECTURE.md`, `DESIGN.md` (לרבות `wireframes.png`, `style-guide.png`, `mockups.png`).

**היקף מחייב:** מוצר בעל **עמוד אחד** בעברית וב-RTL. התצוגות המכונות בתמונות "מסך הבית" ו"מסך בדיחה" הן מצבים של אותו עמוד; **מסך אודות**, קישורי מדיניות, שיתוף ותמונות בדיחה שנוצרות אוטומטית אינם נכללים במוצר. אין Database או Authentication.

## Milestone 1 – בסיס הפרויקט וממשק שימושי ✅

**מטרה:** להעמיד אפליקציית Web עובדת, שניתן להריץ ולבדוק, עם מבנה הממשק המאושר לפני חיבור שירות ה-AI.

**מה יש לממש:**
- הקמת פרויקט `Next.js (App Router) + React + TypeScript` (Node.js LTS, Next.js בגרסה היציבה העדכנית), עם פקודות הרצה ובנייה מקומיות, `ESLint` ו-`Vitest`. מילוי "פקודות הרצה" ב-`CLAUDE.md`.
- בניית עמוד יחיד רספונסיבי בהתאם ל-`DESIGN.md`: כותרת, כותרת משנה, שדה נושא עם Placeholder וכפתור ✕, מונה תווים, כפתור "צור בדיחה", אזור בדיחה במצב ריק (איור הליצן וטקסט הכוונה), איור הדמויות (ללא הכיתוב האנגלי) ושורת תחתית. האיורים מ-`spec/` מועתקים ל-`public/illustrations/` בפורמט מותאם לאינטרנט. שימוש ב-`CSS Modules` או CSS רגיל; גופנים דרך `next/font`; RTL, צבעים, טיפוגרפיה ורכיבים לפי `DESIGN.md`. כל הטקסטים לפי טבלת הטקסטים שב-`DESIGN.md`.
- פונקציית ספירת התווים המשותפת (`countChars`) וחיתוך ל-100 תווים, עם בדיקות Vitest. התיבה יכולה להיות ריקה. שינוי התיבה לא משנה תוכן שכבר מוצג.
- הדגמה מקומית של מצבי הממשק (המתנה, בדיחה, שגיאה) עם תוכן בדיקה **ללא קריאת OpenAI**; ברור למשתמש שזו הדגמה בלבד ולא יצירת בדיחה אמיתית.

**תוצר מצופה:** אתר מקומי פעיל שבו ניתן להזין נושא, לראות את מבנה העמוד ואת אזור התוצאה ולבחון את העיצוב במכשירים שונים. אין עדיין יצירה אמיתית באמצעות AI.

**Definition of Done:**
- [ ] הפרויקט רץ מקומית; `ESLint`, `next build` ובדיקות `Vitest` עוברים.
- [ ] קיים עמוד מוצר אחד בלבד, ללא מסך אודות, תפריטי ניווט או תכונות שלא אושרו.
- [ ] שדה הנושא מקבל קלט ריק, מציג מונה, מונע קלט מעל 100 תווים וחותך הדבקה ארוכה; כפתור ✕ מופיע רק כשיש טקסט ומנקה אותו; שינוי הנושא בלבד אינו משנה תוצאה מוצגת.
- [ ] הממשק בעברית וב-RTL, בעמודה ממורכזת ברוחב מרבי של 560px, ושמיש במובייל, בטאבלט וב-Desktop בדפדפנים מודרניים.
- [ ] ניתן להציג את מצבי ההמתנה, הבדיחה והשגיאה עם תוכן בדיקה ללא שגיאות, ואין מצג של חיבור AI אמיתי.

## Milestone 2 – יצירת בדיחה אמיתית עם Streaming

**תנאי מקדים (פעולה של המשתמש):** חשבון OpenAI עם קרדיט פעיל, מגבלת הוצאה חודשית, גישה למודל `gpt-5` ואימות ארגון אם OpenAI דורשת אותו לצורך Streaming. Claude ידריך צעד אחר צעד בתחילת ה-Milestone.

**מטרה:** לספק את יכולת הליבה המלאה מקצה לקצה: הזנת נושא וקבלת בדיחה בעברית בהדרגה דרך Backend מאובטח.

**מה יש לממש:**
- יצירת `POST /api/joke` ב-`Next.js Route Handler` עם `Node.js Runtime`, אימות קלט בצד השרת (כולל 100 תווים באמצעות `countChars`) ובחירת נושא כללי עבור קלט ריק או רווחים בלבד.
- חיבור ל-`OpenAI Responses API` באמצעות ה-`OpenAI JavaScript SDK` הרשמי והמודל **`gpt-5` בלבד**, עם `reasoning.effort: "minimal"` ו-`max_output_tokens: 1000`. יצירת בדיחה אחת בכל בקשה, בעברית בלבד, כטקסט נקי ולפי מדיניות התוכן (PRD, FR-02א).
- ניהול `OPENAI_API_KEY` בצד השרת בלבד באמצעות `.env` שאינו מועלה ל-Git; יצירת `.env.example` ללא ערכים סודיים והעתקתו ל-`.env` (לפי `CLAUDE.md`).
- הזרמת טקסט מהשרת לדפדפן ב-`HTTP Streaming` לפי חוזה ה-`SSE` שב-`ARCHITECTURE.md` (`delta`, `complete`, `error`), עם מחוון המתנה עד הטקסט הראשון ועדכון אזור התוצאה בהדרגה. בדיקות Vitest לאימות הקלט ולפרסור הזרם.
- בלחיצה חדשה, החלפת הבדיחה הקודמת בבדיחה אחת חדשה; אין שמירת היסטוריה. תוצאה נחשבת להושלמה רק לאחר אירוע `complete`.

**תוצר מצופה:** אפשר לכתוב "חתולים" או להשאיר את התיבה ריקה, ללחוץ "צור בדיחה" ולראות בדיחה אמיתית בעברית מופיעה בהדרגה באותו עמוד.

**Definition of Done:**
- [ ] בשני התרחישים — נושא מוזן ונושא ריק — מתקבלת בדיחה אחת אמיתית באמצעות `gpt-5` דרך ה-Backend, והטקסט מוצג ב-Streaming; עד הטקסט הראשון מוצג "יוצר בדיחה...".
- [ ] נושא לועזי מניב בדיחה בעברית; יצירה נוספת מחליפה את התוצאה הקודמת ולא מוסיפה רשימת בדיחות.
- [ ] הבדיחה היא טקסט עברי נקי: בלי הקדמה, בלי סימני Markdown ובלי אנגלית; נושא רגיש מניב בדיחה עדינה או סירוב מנומס.
- [ ] בקשת API עם נושא מעל 100 תווים או בקשה לא תקינה נדחית בשרת, גם ללא שימוש בממשק.
- [ ] השלמה מזוהה לפי אירוע `complete`, ולא רק לפי סגירת החיבור; תשובה `incomplete` אינה נחשבת להשלמה.
- [ ] אין מפתח API, Prompt שרת או מידע סודי בחבילת ה-Frontend, בתגובות API או ב-GitHub; לא מתבצעת קריאת OpenAI ישירה מהדפדפן.
- [ ] `ESLint`, `next build` ובדיקות `Vitest` עוברים, וזרימת הבקשה מקצה לקצה עובדת בסביבת פיתוח מקומית.

## Milestone 3 – עצירה, העתקה וטיפול במקרי קצה

**מטרה:** להשלים את כל ההתנהגויות שהמשתמש צריך במהלך יצירה מוצלחת, עצירה או כשל, ללא הוספת מסכים.

**מה יש לממש:**
- החלפת "צור בדיחה" ב-"עצור" בזמן `Streaming`; ביטול באמצעות `AbortController` והעברת ביטול ל-Backend/OpenAI ככל שניתן. הגנה מפני מקטעים מאוחרים של בקשה ישנה (`requestId` או מנגנון שקול).
- השארת הטקסט החלקי בעת עצירה או ניתוק, וחזרה לאפשרות ליצור בדיחה חדשה.
- כפתור "העתק בדיחה" עם `Clipboard API`, מוצג **רק** כשהבדיחה הושלמה בהצלחה; משוב "הועתק!" לכשתי שניות; הודעה בעברית בכשל העתקה, ללא חשיפת שגיאה טכנית.
- הודעות שגיאה בעברית (לפי טבלת הטקסטים ב-`DESIGN.md`) והזדמנות לנסות שוב בכשל רשת, כשל שירות AI, קטיעת Stream, תשובה `incomplete` ותגובה חריגה. טיפול בתשובת `429` של WAF גם כאשר הגוף אינו `SSE` או JSON.
- הבחנה נכונה בין `completed`, `stopped`, `error` ובין היעדר אירוע `complete`; מניעת העתקת טקסט חלקי דרך הכפתור.
- בדיקות Vitest למיפוי תשובות שגיאה (כולל `429` עם גוף שאינו JSON) להודעה העברית הנכונה.

**תוצר מצופה:** משתמש יכול לעצור יצירה, להעתיק בדיחה שהושלמה, ולהמשיך להשתמש באתר בצורה צפויה גם לאחר ניתוק רשת או תקלה בשרת.

**Definition of Done:**
- [ ] בזמן Streaming מוצג "עצור"; לחיצה עליו עוצרת הצגת מקטעים חדשים ושומרת את הטקסט החלקי שכבר התקבל.
- [ ] טקסט חלקי שנעצר או נקטע אינו ניתן להעתקה דרך הכפתור; בדיחה שהושלמה מועתקת במלואה ל-Clipboard ומוצג "הועתק!".
- [ ] ניתוק לפני קבלת טקסט, ניתוק לאחר קבלת טקסט ולפני `complete`, תקלה ב-AI והיעדר אינטרנט בעת ניסיון יצירה מציגים הודעות שגיאה בעברית ומאפשרים ניסיון חדש.
- [ ] גם כאשר הבקשה הסתיימה ללא `complete`, הממשק אינו מסמן אותה כהצלחה.
- [ ] בקשות ישנות או אירועים שהגיעו לאחר ביטול אינם משנים תוצאה של בקשה חדשה.
- [ ] בדיקות Vitest מאמתות שתשובת `429` מוצגת כהודעת הגבלת הקצב בעברית ואינה חושפת תגובת שרת גולמית; בדיקת אכיפת WAF אמיתית תתבצע ב-Milestone 5.

## Milestone 4 – PWA ו-Offline

**מטרה:** לאפשר התקנה של האתר כאפליקציה ופתיחת הממשק ללא אינטרנט, בבדיקה מקומית ולפני העלאה לאוויר.

**מה יש לממש:**
- `Web App Manifest` (שם, צבעים ו-`lang`/`dir` לפי `DESIGN.md` ו-`ARCHITECTURE.md`), קובץ SVG של אייקון האפליקציה וכל הגדלים הנגזרים ממנו (192, 512, `maskable`, `apple-touch-icon`).
- `Service Worker` ייעודי ו-`Cache Storage` עבור `App Shell` בלבד, לפי אסטרטגיית ה-Cache שב-`ARCHITECTURE.md` (ניווט Network First; קבצים סטטיים, אייקונים וגופנים Cache First). רישום ה-Service Worker רק בגרסת Production. בקשות `POST /api/joke` אינן נשמרות ב-Cache; תשובות API מוגדרות `no-store`.
- פתיחת הממשק גם ללא אינטרנט אחרי ביקור מחובר; ניסיון ליצור בדיחה ללא רשת מציג הודעת שגיאה בעברית. ההתקנה מתבצעת דרך אפשרויות הדפדפן, **ללא כפתור התקנה באתר**.

**תוצר מצופה:** בגרסת Production מקומית (`next build` + `next start`) אפשר להתקין את האתר דרך הדפדפן, ולפתוח אותו מחדש גם כשהאינטרנט מנותק.

**Definition of Done:**
- [ ] בגרסת Production מקומית, הדפדפן מזהה את האתר כניתן להתקנה ומציג את השם והאייקון הנכונים; אין כפתור התקנה בתוך האתר.
- [ ] אחרי טעינה מחוברת, ממשק האפליקציה נפתח גם ב-Offline עם הגופנים והעיצוב הנכונים; לחיצה על "צור בדיחה" ללא רשת מציגה הודעה בעברית ולא מחזירה בדיחה מתוך Cache.
- [ ] `POST /api/joke` מוחרג מ-Cache; כותרות תשובת API מונעות שמירה.
- [ ] בהרצת פיתוח (`next dev`) ה-Service Worker אינו פעיל.
- [ ] `ESLint`, `next build` ובדיקות `Vitest` עוברים.

## Milestone 5 – העלאה לאוויר, הגנת שימוש ובדיקות קבלה

**תנאי מקדים (פעולה של המשתמש):** חשבון Vercel מחובר ל-GitHub. Claude ידריך צעד אחר צעד בחיבור, בהגדרת המפתח ובהגדרת כלל ה-WAF.

**מטרה:** להעמיד גרסה ציבורית ב-HTTPS עם פריסה אוטומטית מ-`main` והגנת Rate Limiting, ולוודא שכל זרימות המוצר עובדות באתר החי.

**מה יש לממש:**
- חיבור GitHub ל-Vercel עם `Production Deployment` אוטומטי מכל Push ל-`main`, כולל `Build` אוטומטי ו-HTTPS. אין שימוש בסביבת Preview (ראו `ARCHITECTURE.md` 2.7).
- הגדרת `OPENAI_API_KEY` ב-Vercel Environment Variables **לסביבת Production בלבד**; בדיקת `maxDuration` ותאימות מגבלות זמן של Functions ל-Streaming.
- הגדרת `Vercel WAF Rate Limiting` ל-`POST /api/joke`: חמש בקשות בדקה לכל כתובת IP בחלון קבוע של 60 שניות, החזרת `429` בעת חריגה, ללא מכסה יומית וללא Database. **הכלל מוגדר לפני שהכתובת הציבורית משותפת עם אחרים.**
- בדיקות קבלה של כל זרימות המוצר באתר החי בדפדפנים ומכשירים רלוונטיים, יחד עם בדיקת הגבלות Hosting, הוצאות API ולוגים תפעוליים בסיסיים ללא תוכן בדיחות.

**תוצר מצופה:** גרסה ציבורית נגישה ב-HTTPS עם Deployment אוטומטי מ-GitHub, יצירת בדיחות מוגנת Rate Limiting, התקנה כ-PWA וממשק שנפתח Offline.

**Definition of Done:**
- [ ] Push ל-`main` יוצר Production Deployment אוטומטי ב-HTTPS, ללא פריסה ידנית.
- [ ] באתר החי, בדיקה מבוקרת מאותה כתובת IP מאמתת שהבקשה השישית באותו חלון זמן נדחית ב-`429` **לפני** קריאה ל-OpenAI, והודעת החריגה מוצגת בעברית.
- [ ] ה-API Key זמין ל-Backend בלבד, לסביבת Production בלבד; אינו נחשף בדפדפן, בבנייה או ב-Repository.
- [ ] באתר החי: התקנה כ-PWA ופתיחה Offline עובדות.
- [ ] בדיקות קבלה עוברות באתר החי: נושא ריק/מוזן/לועזי/רגיש, 100 תווים והדבקה ארוכה, כפתור ✕, Streaming ומחוון המתנה, עצירה, העתקה לאחר השלמה בלבד, החלפת בדיחה, כשלי רשת ושירות, Rate Limiting ו-Offline.
- [ ] נבדקו מגבלות Vercel, תנאי התוכנית הרלוונטית, זמינות GPT-5 ומגבלת ההוצאה ב-OpenAI.

## Development Execution Rules – כללי ביצוע הפיתוח

**הוראה מחייבת ל-AI שמבצע את הפיתוח:**

1. יש לפתח את ה-Milestones **לפי הסדר בלבד**, על בסיס מסמכי ה-PRD, הארכיטקטורה והעיצוב, ללא הוספת פיצ'רים שלא אושרו.
2. בסיום **כל Milestone**, יש **לעצור את הפיתוח**, להציג למשתמש את התוצר שהושלם, איך ניתן לבדוק אותו ואת תוצאות הבדיקות מול **כל סעיף** ב-Definition of Done (עבר / נכשל / טרם נבדק), כולל תקלות או חסמים פתוחים.
3. **אסור להתחיל את ה-Milestone הבא ללא אישור מפורש של המשתמש**, גם אם כל הבדיקות עברו.
4. אין לסמן Milestone כ-Done כאשר תנאי סיום מהותי לא אומת. אם בדיקה דורשת שירות חיצוני, הרשאה או הגדרת חשבון, יש להסביר למשתמש במילים פשוטות מה נדרש ולהמתין להשלמתו.
5. אין להשתמש ב-Mockups כהיתר להרחיב את ה-PRD: מסך האודות וקישורי המדיניות שמופיעים בתמונות אינם חלק ממסלול הפיתוח הנוכחי.
